# Hopline · Cloudflare 代理订阅面板

> **Hopline —— 部署在 Cloudflare Workers / Pages 的代理订阅面板**，单文件同时实现 VLESS / Trojan / XHTTP 多协议代理与图形化配置：`/<PATH>` 进入面板，`/sub` 输出订阅；内置优选域名与在线优选 IP 来源、ECH 加密、落地与出站代理（含可配置的地区反代）及地区 / 运营商 / IP 版本多维筛选，只需设置 `PATH` 与 `ADMIN` 两个环境变量即可部署（UUID 等其余均可选），绑定 KV 后改完即生效。

# 更新日志 _V2.2.0

### ⚠️ 升级必读：环境变量调整

**必填项只剩两个：`PATH`（访问路径）与 `ADMIN`（管理密码）。** UUID 及其余变量全部可选。

| 新名称 | 旧名称（仍兼容） | 说明 |
|---|---|---|
| `PATH` | `D` | **必填**，面板 / 订阅 / 节点共用的访问路径 |
| `ADMIN` | `admin` | **必填**，管理密码（不变） |
| `UUID` | `U` | 可选，未设置时自动生成 |
| `OUTBOUND_PROXY` | `OUTBOUND`、`S` | 出站代理 |
| `ENABLE_ECH` | `ECH` | 开启 ECH |
| `ENABLE_TROJAN` | `TROJAN` | 开启 Trojan |
| `CONFIG_KV`（KV 绑定变量名） | `K` | KV 命名空间绑定 |

`ADMIN_USER`、`HOST`、`PROXYIP`、`TROJAN_PASSWORD`、`ALPN` 名称不变。新旧名称同时存在时新名称优先，**已部署的 Worker 无需改名即可继续工作**，只有下面这一项需要处理：

- **旧版没有设置 `D` 的部署（路径默认等于 UUID）升级后必须设置 `PATH`**：把 `PATH` 设为原来的 UUID 值，节点与订阅地址完全不变。未设置 `PATH`（或值不合法）时，所有请求返回设置说明（503）而不是 404。在面板里改过「面板路径」（保存在 KV）的，同样把 `PATH` 设为那个值——面板路径现在只来自环境变量，面板中只读

### ✨ 改进

- **`PATH` 成为必填的访问路径，与 UUID 解耦**：面板、订阅（`/<PATH>/sub`）与节点（WebSocket / XHTTP）共用 `/<PATH>`，UUID 只作节点身份。此前路径默认等于 UUID，改 UUID 会同时改变面板与节点路径；现在互不影响。订阅仍可从 `/<UUID>/sub` 取得（V2.1.7）。`PATH` 去掉首尾 `/`，只允许字母、数字及 `. _ ~ -`，不能是 `login`、`version`
- **UUID 可选**：未设置时首次访问随机生成一个 v4 UUID 并保存到 KV，之后一直沿用（此前未设置会每次请求都生成新的）；可在面板查看与修改，KV 中已有的其它设置保留。**未绑定 KV 时没有地方保存，必须手动设置 `UUID`**（否则返回设置说明）。KV 跨机房最终一致，部署后请先自己打开一次面板，避免两个机房同时首次访问各生成一个
- 面板「面板路径」改为只读并说明来源；错误提示与文档中的 KV 绑定变量名统一为 `CONFIG_KV`
- 新增测试：必填项缺失 / 非法的设置说明、`PATH` 与 UUID 解耦、UUID 自动生成并持久化（含并发首次访问）、无 KV 且无 UUID、新旧变量名与优先级、KV 新旧绑定名（测试 90 → 95 项）；另在 workerd 中验证了缺失 / 完整 / 旧变量名三类部署的实际响应

# 更新日志 _V2.1.3

### 🐛 BUG 处理

- **访问 Cloudflare 上的网站时连接可能永久挂起**：反代域名的 DNS 解析此前在多个请求之间共享「进行中」的查询，而 Workers 中 fetch 归属发起它的请求——客户端在解析期间断开时，该查询被取消，共享它的其它连接以及之后同一实例上所有需要反代的连接都会永远等待（已在 workerd 中复现：A 断开后 B 与之后的 C 全部挂起）。现在只缓存解析完成的结果，并给反代等待加了 10 秒总上限

### ⚡ 优化（访问 Cloudflare 上的网站时的 CPU 占用）

- **内置地区反代域名只查 A 记录**：实测 14 个内置地区域名都没有 TXT 记录，此前每次冷解析都多查一次 TXT；自定义 PROXYIP / 自定义反代仍查 TXT
- **学习型路由取代 V2.0.24 的目标域名 DNS 检查**：此前每个新域名（包括不在 Cloudflare 上的网站）都要额外查一次 DNS 判断是否托管在 Cloudflare。现在改为：直连失败、由反代接通的站点记住 30 分钟，之后的连接直接走反代，不再发注定失败的直连、也不查 DNS；直连只是慢但最终能通的站点不记录；按记录走反代却失败时删除记录并回落直连
- **目标为 Cloudflare IP 时不再尝试直连**：直接走反代（反代不通时才回落直连），省掉一次注定失败的连接
- 本地 workerd 实测（冷实例、每次连接访问 Cloudflare 上的站点）：每次连接 CPU 约 5.2ms → 3.8ms，DoH 查询 5 次 → 2 次；不在 Cloudflare 上的站点不再有任何额外 DNS 查询
- 新增测试：直连挂起时窗口到期由反代接管、学习型路由（记录 / 不记录 / 回落并删除）、内置反代只查 A、Cloudflare IP 目标不发直连、解析结果缓存复用（测试 79 → 83 项）

# 更新日志 _V2.0.25

### ⚡ 优化

- **WebSocket（VLESS-WS / Trojan）下行合并小块**：运行时的 socket 每次只读出约 4KB，此前逐块发送，1MB 就是约 256 条 WS 消息，每条都有固定 CPU 开销，看视频时仍会偶发 `Worker exceeded CPU time limit`。现在读满 4KB 时把已到达缓冲区的后续数据合并成最多 64KB 一条消息；读不满（缓冲已空，如网页交互）时直接发出，不增加延迟。本地 workerd 实测：每 MB CPU 约 13ms → 7ms，消息数约 52000 → 3500（200MB），下行逐字节校验一致，小包往返延迟不变
- **WebSocket 不再协商压缩（permessage-deflate）**：客户端请求压缩时运行时会自动启用，对视频等已压缩数据毫无收益，实测每 MB CPU 约 12ms → 49ms。现在 101 响应声明不压缩，运行时据此关闭压缩（Xray / Mihomo 默认不请求压缩，其他客户端可能请求）；旧兼容日期部署本就不压缩，不受影响
- 新增测试：下行小块合并（顺序完整、64KB 上限、后续数据单独发出、目标结束关闭 WS）、101 响应不协商压缩（测试 75 → 77 项）

# 更新日志 _V2.0.24

### 🐛 BUG 处理

- **XHTTP 看视频变得极慢（日志大量 `Worker exceeded CPU time limit`）**：免费版每个请求只有 10ms CPU，而 XHTTP 的每条代理连接就是一个长请求；此前下行与上行都在 JS 里逐块搬运（read → enqueue / write），看 YouTube 时几 MB 数据就超出 CPU 上限，连接被限流到几乎不动，重启客户端（换新连接）才恢复。现在数据面全部交给运行时原生管道（`pipeTo`），JS 只处理握手：本地 workerd 实测每 MB 的 CPU 从约 15ms 降到约 2ms（剩余主要是运行时自身的 I/O），单连接吞吐提升约 7 倍，挂起 116 条不读的流时内存 342MB → 91MB；客户端断开同样立即释放目标连接，20MB 上行回显逐字节一致
- **直连优先窗口 300ms → 1.5s，并识别 Cloudflare 托管目标**：此前目标站直连握手超过 300ms（跨境常见）就会被第三方地区反代接管，该连接此后一直走反代（多一跳、带宽受限）。现在直连只要在 1.5s 内能通就用直连；直连失败仍然立即换反代；目标域名的 A 记录全部在 Cloudflare 段（直连必被回环保护拦截）时，由并发 DoH 查询（带缓存）识别后立即让反代接管，不必等满窗口
- 新增测试：慢直连（600ms）不被反代抢走（测试 74 → 75 项）
- 说明：Trojan 节点是 Trojan over WebSocket（Workers 只能收 WebSocket / HTTP 流量，无法监听裸 TCP 的原生 Trojan），所以客户端传输层设置（ws / TLS / path / host）与 VLESS-WS 相同，区别只在协议头与密码

## 一、项目概述与兼容性

| 项 | 内容 |
|---|---|
| 项目名称 | **Hopline · Cloudflare 代理订阅面板** |
| 当前版本 | v2.2.1 |
| 运行环境 | Cloudflare Workers / Pages |
| 部署形态 | 单文件 Worker/Pages（`Hopline.js`，由 `src/` 构建生成，见「九、开发与构建」） |
| 数据存储 | Cloudflare KV（绑定变量 **CONFIG_KV**）；未绑定时面板无法保存，仅环境变量生效，且必须设置 `UUID` |
| 面板入口 | `https://你的域名/<PATH>`（`PATH` 为必填环境变量；面板、订阅与节点共用此路径） |
| 订阅入口 | `https://你的域名/<UUID>/sub`（按客户端 UA 自动识别格式；也可追加格式后缀强制指定，如 `/sub/clash`、`/sub/singbox`） |
| 配置 API | `https://你的域名/<PATH>/api/config`（GET 读取 / POST 保存，支持只提交部分字段；需登录） |

### 1.1 节点下发逻辑

- **节点来源**：下发「原生地址（默认关）+ 优选域名节点 + 在线优选 IP（自定义 API / HostMonit / uouin / 微测网）」，IP 一律只保留 Cloudflare 段地址，不生成随机 IP，也不内置静态 IP 池
- **端口**：默认只下发 TLS 端口节点（「节点配置 → 仅 TLS 端口」）；关闭后每个 443 节点另追加一个 80 明文节点（名称带「·80」），来源自带的 8080 / 2052 等明文端口原样下发；自定义域名使用明文节点需在 Cloudflare 关闭「始终使用 HTTPS」；开启 ECH 时始终只下发 TLS 端口节点
- **节点命名**：同时开启多种协议时，同一地址的 Trojan 节点名加「.T」、XHTTP 加「.X」（VLESS 保持原名）；不同地址同名时依次加「·2」「·3」，所有格式节点名唯一
- **Sing-box**：生成 sing-box 1.12+ 格式配置（二进制 .srs 规则集经 jsDelivr 下载）；官方 sing-box 内核不支持 XHTTP，Sing-box 订阅中不含 XHTTP 节点。GUI.for.SingBox 请用其「导入 sing-box 配置」插件导入订阅
- **节点上限**：单次订阅最多下发 500 个节点（按免费计划 10ms CPU 限制设定），来源不足时按实际数量下发，不补足；不做轮询换新（来源数据不变时每次下发相同的节点）

## 三、部署说明

### Worker 部署

1. 登录 Cloudflare 控制台 → Workers 和 Pages → 新建 Worker
2. 将仓库中的 `Hopline.js` 全文粘贴到 Worker 代码编辑器
3. 设置两个**必填**环境变量：**`PATH`** = 面板、订阅与节点共用的访问路径（如 `mypanel`，只能含字母、数字及 `. _ ~ -`），**`ADMIN`** = 管理密码（未设置时面板与管理接口一律禁用）。其余变量均可选；`UUID` 留空时首次访问自动随机生成并保存到 KV
4. （推荐）创建 **KV 命名空间** 并在 Worker 设置中绑定，变量名设为 **`CONFIG_KV`**——配置面板保存后持久化，也用于保存自动生成的 UUID（不绑定 KV 则必须设置 `UUID` 变量）
5. 部署后访问 `https://你的域名/<PATH>` 进入图形化配置面板

### Pages 部署

1. 登录 Cloudflare 控制台 → Workers 和 Pages → 新建 Pages 项目
2. 将 `Hopline.js` 放到项目目录（或压缩为 zip 上传），框架选择「无」
3. 设置 **环境变量 `PATH`** 与 **`ADMIN`**（同上）
4. （推荐）创建 KV 命名空间并在 Pages 设置中绑定，变量名设为 **`CONFIG_KV`**
5. 部署后访问 `https://你的域名/<PATH>` 进入图形化配置面板

### 登录与访问

- 访问 `https://你的域名/<PATH>` 直接进入面板；`PATH` 未设置或格式不正确时，所有请求都返回设置说明（503）
- 必须设置 `ADMIN` 管理密码：未设置时面板返回「已禁用」、管理接口不可用；设置后访问面板需先登录（PATH 路径 + 用户名 + 密码校验；用户名默认 `admin`，可在面板或用 `ADMIN_USER` 修改）
- 订阅地址：`https://你的域名/<UUID>/sub`（下方「订阅地址」模块有各客户端一键复制链接）

## 四、环境变量与配置变量

> 优先级：**KV 配置 > 环境变量 > 默认值**
>
> 环境变量只在面板里没有改成别的值时生效：面板保存时，与环境变量相同的值不会写入 KV（之后修改环境变量立即生效），改成不同的值才保存为覆盖。`PATH`、`ADMIN` 设置后面板中只读。

### 4.1 基础配置

> **必填只有 `PATH` 与 `ADMIN` 两项**，其余全部可选。旧版的短变量名（`U`、`D`、`S`、`K`、`ECH`、`TROJAN`）仍然兼容，已部署的 Worker 无需改动；新旧名称同时存在时新名称优先。

| 变量 | 值 | 说明 |
|---|---|---|
| `PATH`（旧名 `D`） | 访问路径 | **必需**。面板、订阅（`/<PATH>/sub`）与节点（WebSocket / XHTTP）共用此路径；只能含字母、数字及 `. _ ~ -`，不能是 `login`、`version`；首尾的 `/` 自动去掉。未设置或非法时所有请求返回设置说明（503）；设置后面板中只读，修改后节点路径随之改变，客户端需重新更新订阅 |
| `ADMIN`（旧名 `admin`） | 管理密码 | **必需**，未设置时面板与管理接口一律禁用；设置后面板中该项只读 |
| `UUID`（旧名 `U`） | 你的 UUID | 可选，VLESS 用户 ID（节点身份）。**留空则首次访问时随机生成并保存到 KV**，之后一直沿用，可在面板查看与修改；未绑定 KV 时没有地方保存，必须手动设置。面板里修改后以面板为准 |
| `ADMIN_USER` | 管理用户名 | 可选，登录时与密码一起校验（区分大小写），默认 `admin`；设置后面板中该项只读 |
| `HOST` | 自定义 SNI / Host | 可选，节点的 SNI 与 WS Host；留空用访问所用的域名 |
| `CONFIG_KV`（旧名 `K`） | KV 命名空间绑定 | 可选（推荐），在 Worker / Pages 设置里绑定 KV 命名空间时使用的变量名；绑定后面板配置才能保存 |

### 4.2 协议与传输

| 变量 | 值 | 说明 |
|---|---|---|
| `ENABLE_ECH`（旧名 `ECH`） | true / 1 | 启用 ECH 加密客户端握手（开启后自动仅 TLS 端口） |
| `ENABLE_TROJAN`（旧名 `TROJAN`） | true / 1 | 启用 Trojan 协议（默认禁用） |
| `TROJAN_PASSWORD` | 自定义密码 | Trojan 密码，留空用 UUID |
| `ALPN` | h2 / http/1.1 | ALPN 协商（逗号分隔），VLESS / Trojan / XHTTP 链接、Clash、Sing-box 均按此下发；留空时 ws 用 http/1.1、XHTTP 用 h2 |

### 4.3 优选与出站

| 变量 | 值 | 说明 |
|---|---|---|
| `PROXYIP` | host 或 host:port | 反代 / 落地 IP：填写后作为固定出口优先使用；留空则直连失败后由地区反代兜底 |
| `OUTBOUND_PROXY`（旧名 `OUTBOUND`、`S`） | `socks5://` / `http(s)://` / `ss://` 地址，或 `user:pass@host:port` | 出站代理（SOCKS5 / HTTP(S) / Shadowsocks） |

### 4.4 面板配置项（保存于 KV）

> 完整字段、默认值与校验规则以 `src/worker/config-schema.js` 中的 `CONFIG_SCHEMA` 为准。保存时逐项校验，未登记的字段会被忽略；`PATH`、`ADMIN` 等环境变量设置后对应项在面板中只读。

| 配置项 | 说明 |
|---|---|
| `uuid` / `adminUser` / `admin` / `host` | 基础配置（同环境变量，面板可视化编辑；`path`、`admin` 由环境变量提供，面板只读） |
| `subUrl` | 自定义订阅路径：`/<别名>/sub` 输出订阅（别名下不开放面板与管理接口）；留空为 `/<UUID>/sub`。面板路径下的 `/sub` 始终可用 |
| `enableVless` / `enableTrojan` / `enableXhttp` | 协议开关（默认 VLESS 与 XHTTP 开、Trojan 关） |
| `trojanPassword` | Trojan 密码 |
| `alpn` / `tlsOnly` | ALPN 协商 / 仅 TLS 端口节点（默认开启；关闭后 443 节点追加 80 明文节点，来源自带的明文端口原样下发） |
| `ech` / `echHost` / `echDns` | ECH 开关 / 自定义 ECH 域名 / ECH DoH |
| `filter.region` | 地区（多选数组）：`['all']` 或 HK / TW / US / SG / JP / KR / DE 的组合 |
| `filter.ipType` | IPv4 / IPv6（默认只有 IPv4） |
| `filter.isp` | 移动 / 联通 / 电信 |
| `src.native` / `src.prefDomain` / `src.prefIp` | 地址来源：原生地址 / 优选域名 / 优选 IP |
| `ipsrc.hostmonit` / `ipsrc.uouin` / `ipsrc.wetest` / `ipsrc.api1` / `ipsrc.api1Url` / `ipsrc.api2` / `ipsrc.api2Url` | 优选 IP 来源开关与两个自定义优选 API 地址（默认：HostMonit 开、uouin 开、微测网关、自定义 API 关；开启 API 但未填地址时保存会报错） |
| `prefDomains` | 优选域名：每行一个纯主机名（最多 30 个），**整体替换**内置的 14 个域名；留空使用内置列表。影响域名节点与 IPv6 解析（IPv6 解析：同时勾选 IPv4 与 IPv6 时只解析前 12 个，仅 IPv6 时前 25 个） |
| `relay.mode` / `relay.region` / `relay.region2` / `relay.custom` | 内置地区反代：`builtin`（默认，按 Worker 机房自动选地区，可固定首选 / 次选地区，次选 `none` 表示不使用）/ `custom`（只用 `relay.custom` 中最多 3 个 `host[:port]`）/ `off`（不使用地区反代，只直连 / 出站代理） |
| `proxyIP` / `outboundProxy` / `outboundMode` | 反代落地 IP / 出站代理 / 出站模式（`''` 默认、`no` 直连优先、`only` 仅代理） |

## 六、地址来源与优选

### 6.1 地址来源

默认节点池由「仪表盘 → 地址来源」三项组装：

| 来源 | 说明 |
|---|---|
| **原生地址**（默认关） | 工作器域名直接作为节点下发 |
| **优选域名**（默认开） | 直接下发域名，客户端连接时自行解析到当前最优的 Cloudflare 边缘 IP；列表可在「优选配置 → 优选域名」自定义（整体替换内置列表，留空用内置的 14 个） |
| **优选 IP**（默认开） | 「优选配置 → 优选 IP 来源」中开启的在线来源：HostMonit、uouin、微测网、自定义优选 API 1 / 2 |

所有来源都没有产出时用官方域名（cloudflare.com 等）兜底，订阅不会为空。V2.0.17 起已移除「自定义订阅」与「随机优选」两种订阅模式及 `YX` 环境变量。

### 6.2 自己测速

面板不提供在线测速。请用本地工具（如 CloudflareSpeedTest）在自己的网络下测速，把结果托管成一个地址（纯 IP 行 / CSV，行内可写 `IP:端口#名称`），填入「优选配置 → 优选 IP 来源」的自定义优选 API 1 / 2。

### 6.3 地区与命名

- 带地区标记的数据行（如「IP:端口#地区随机 \| 香港 HK」）显示中文地区名：香港 / 台湾 / 日本 / 美国 / 新加坡 / 韩国 / 德国
- 优选域名节点命名为「优选域名-XX」；优选 IP 来源中无法确定地区的统一为「优选IP-XX」（IPv6 域名解析结果为「优选IP-V6-XX」）；数据源自定义名称（如 `JP-A-147`）原样保留
- 「节点地区」筛选只剔除名称明确标记为其它地区的节点。各内置来源都是不带地区的 Cloudflare 任播 IP / 域名（落地机房取决于客户端网络），地区筛选不改变其节点构成；需要按地区挑选请让自定义优选 API 返回带地区名的来源
- HostMonit 实时优选（`api.hostmonit.com`，默认开）节点按线路命名为「移动-01 / 联通-01 / 电信-01」，面板「运营商偏好」可据此筛选；接口失效时沿用上次结果，由其它来源兜底
- uouin 分线路优选（`api.uouin.com`，默认开，可在面板关闭）：电信 / 联通 / 移动 / 多线 / IPv6 各约 10 个 IP，节点名如「电信-U01」。使用的是对方网站的内部接口（非开放 API，签名模仿其网站前端），对方可能随时更换签名或封禁，届时静默失效；10 分钟缓存以减少请求
- 微测网优选（`wetest.vip` 公开页面，默认关）：IPv4 / IPv6 各一页，移动 / 联通 / 电信各 5 个 IP，约每 15 分钟更新，节点名如「移动-W01」「移动-W6-01」；是 HTML 表格而非开放 API，版式变化时静默失效；只拉取所选 IP 类型对应的页面
- 自定义优选 API 1 / 2（默认关）：填写返回 IP 列表的地址（纯 IP 行 / CSV / HTML 线路表 / base64 订阅 / `sub://`），只保留 CF 段 IP；开启但未填地址时保存会报错
- 在线来源排列顺序：自定义 API 1 / 2 → HostMonit → uouin → 微测网；结果缓存 10 分钟（绑定自定义域名时，同一机房的实例通过 Cache API 共享缓存；workers.dev 下 Cache API 不生效，各实例各自缓存），缓存未命中时每个开启的来源占用 1 个子请求
- 非 CF 段的中转 IP（如 bestcf 地区池，实测全部为第三方中转）可获知部署域名与连接元数据，无法作为入口：所有来源一律只保留 Cloudflare 段 IP，其余丢弃

## 七、性能优化与安全

- **不生成随机补足**：节点全部来自优选域名与在线优选来源；单次订阅最多 500 个节点，来源不足时按实际数量下发
- **DoH 与子请求预算**：优选域名解析 Cloudflare DoH 优先，仅当请求失败时降级阿里 DNS，正常每次解析只计 1 个子请求（反代域名与 UDP DNS 解析同样 Cloudflare 优先、逐个降级，超过 0.7 秒未响应会提前并发下一个）；IPv4+IPv6 混合时只对前 12 个优选域名查询 AAAA。实测单次订阅约 14–20 个子请求，最坏（仅 IPv6、30 个自定义域名、全部来源开启）约 31 个，低于免费版上限 50
- **出站并发竞速**：直连与地区反代（内置或自定义，可在面板关闭）同时发起，取先握手成功的一路，败者连接立即释放；直连有 1.5s 优先窗口（可直连的站点不绕第三方反代）；目标为 Cloudflare IP 时不发直连、直接用反代；直连失败、由反代接通的站点会被记住 30 分钟，之后直接走反代（不再发直连、不查 DNS）。目标站在 Cloudflare 上时不再白等约 6 秒；出站模式（默认 / 直连优先 / 仅走代理）决定出站代理与直连、反代的先后
- **首包判定**：地区反代与「反代 / 落地 IP」只能转发 TLS 流量（按 SNI 路由），非 TLS 首包（Telegram MTProto、明文 HTTP 等）只走直连与出站代理
- **WS 0-RTT 早数据**：TLS WebSocket 节点带 `?ed=2048`（Sing-box 用 `max_early_data`），客户端把首包放进握手请求头，服务端握手时即建连，省约 1 个往返；早数据校验不通过时按普通连接处理
- **VLESS 响应头提前下发**：头部解析成功即回 2 字节响应头，首包等待上限 80ms，避免与部分客户端（mihomo 等）互相等待
- **SWR 容灾缓存**：外部优选源拉取失败时沿用上一轮有效结果（10 分钟缓存；绑定自定义域名时同一机房共享）
- **路径与 UUID 鉴权**：请求路径与 `PATH` 一致才进入面板 / 代理，VLESS 头部的 UUID 与配置一致才转发；面板必须设置管理密码并以用户名 + 密码登录，订阅别名路径只输出订阅
- **非法路径拦截**：无效路径直接 404；配置读取走 KV 边缘缓存（30 秒），KV 读取失败或配置损坏时拒绝保存，且没有环境变量 UUID 时返回 503，避免用默认值覆盖已有配置或重新生成 UUID

## 九、开发与构建

`Hopline.js` 是构建产物（部署时直接粘贴它即可），源码位于 `src/`：

| 路径 | 内容 |
|---|---|
| `src/worker.js` | 入口：环境变量说明与 `// @include worker/xxx.js` 清单，构建时按顺序拼接 |
| `src/worker/*.js` | 服务端逻辑，按主题拆分：`config-schema`（字段表 `CONFIG_SCHEMA`）、`config`（加载 / 保存）、`protocol`（VLESS / Trojan 头、DoH）、`outbound-proxies` / `relay`（出站与反代）、`proxy`（WS / XHTTP）、`ip-sources` / `nodes`（优选来源与节点生成）、`formats`（各客户端格式）、`subscription`、`router`（鉴权、路由、管理 API）等 |
| `src/panel/panel.html` | 管理面板页面结构（`@include` 引入样式与脚本） |
| `src/panel/panel.css` | 面板样式（日间 / 夜间主题） |
| `src/panel/panel.js` | 面板前端脚本（由字段表驱动的表单回填、收集、校验与错误提示） |
| `src/panel/login.html` | 登录页 |
| `build.mjs` | 零依赖构建脚本：拼接 `src/worker/*.js`、内联面板页面，输出 `Hopline.js` |
| `eslint.config.mjs` | 静态检查配置（`npm run lint`，CI 中运行） |
| `test/` | `node:test` 测试（模拟 KV 与 Workers 运行时，无需安装依赖） |

```bash
node build.mjs          # 修改 src/ 后重新生成 Hopline.js（需 Node.js 20.6+，CI 使用 22）
npm test                # 校验 Hopline.js 与 src/ 同步，并运行测试
npm run lint            # eslint 静态检查（通过 npx 获取，仓库本身仍无依赖）
```

**新增一个面板配置项**：在 `src/worker/config-schema.js` 的 `CONFIG_SCHEMA` 中加一行（字段路径、类型、默认值、面板控件 id、校验规则），再在 `src/panel/panel.html` 放一个同 id 的控件即可——默认值、KV 读写白名单、保存校验、面板回填 / 收集 / 未保存标记 / 字段级错误提示都会自动生效；服务端通过 `cfg.<字段>` 读取。

> 请勿直接编辑 `Hopline.js`：CI 会检查它是否与 `src/` 同步。
